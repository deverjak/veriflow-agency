VeriFlow Agency

Claude Code, který si pamatuje,
co jsi mu minulý týden zamítl.

Claude Code that remembers
what you rejected last week.

Agency z obecného asistenta dělá specialisty vázané na jeden repozitář — s pamětí, kterou commituješ, s bránou, která odmítá nepodložené nálezy, a s čísly, která řeknou, jestli se to zlepšuje. Žádná konfigurace, žádný účet, žádná další služba.

Agency turns a general assistant into specialists tied to one repository — with memory you commit, a gate that refuses unsupported findings, and numbers that say whether it is getting better. No configuration, no account, no extra service.

Problém není chytrost. Je to amnézie.The problem is not intelligence. It is amnesia.

Claude Code je výborný. Otevřeš ho, popíšeš úkol, on ho udělá. Zavřeš okno — a je pryč všechno.

Zítra ti navrhne přesně tu věc, kterou jsi včera zamítl s tím, že je to záměr. Za měsíc nedokážeš odpovědět na otázku, jestli ti to vůbec k něčemu je: kolik z toho, co našel, byla pravda? Které jeho otázky mají smysl a které jen šumí? Zlepšil se, když jsi mu upravil instrukce, nebo se jen jinak zamotal?

Nemáš jak to zjistit, protože po běhu nezbyde nic než tvoje paměť. A ta si vzpomene na to poslední, ne na to důležité.

Claude Code is excellent. You open it, describe the task, it does the task. You close the window — and everything is gone.

Tomorrow it proposes exactly the thing you rejected yesterday as deliberate. In a month you cannot answer whether it is worth anything: how much of what it found was true? Which of its questions matter and which are noise? Did it get better when you edited its instructions, or just differently confused?

You have no way to know, because a run leaves nothing behind but your memory. And memory keeps the most recent thing, not the important one.

Jádro věciThe point

Chybějící schopnost není inteligence, ale kontinuita: paměť, kontrola a měřitelnost. Přesně to Agency doplňuje — a nic z toho nedělá model, dělá to nástroj kolem něj.

The missing capability is not intelligence, it is continuity: memory, checking, measurement. That is exactly what Agency adds — and none of it is done by the model, it is done by the tooling around it.

Co to jeWhat it is

Specialista je adresář ve tvém repozitáři. Ne účet, ne plugin, ne řádek v konfiguraci. Leží tam, kde Claude Code už skilly hledá:

A specialist is a directory in your repository. Not an account, not a plugin, not a line of configuration. It sits where Claude Code already looks for skills:

.claude/skills/agency-review-graph/
  pack.json     ← co potřebuje vědět nástroj← what the tool needs to know
  SKILL.md      ← metoda a fakta o tomhle projektu← the method and this project's facts
  references/   ← delší podklady← longer material

Tomu adresáři se říká pack. Commituješ ho jako každý jiný zdroják, reviduješ ho v pull requestu a je celý o tomhle projektu — jeho staging, jeho board, jeho pravidla. Druhý projekt dostane kopii a přepíše si fakta; nesdílí se parametr, kopíruje se specialista.

A pak je tu agency — příkaz, který ho spustí, ohlídá a zaznamená. Nenahrazuje Claude Code, řídí ho. Rozdíl není v modelu, ale v tom, co je kolem běhu.

That directory is called a pack. You commit it like any other source, review it in a pull request, and it is entirely about this project — its staging, its board, its rules. A second project gets a copy and rewrites the facts; nothing is a shared parameter, the specialist is copied.

Then there is agency — the command that runs it, watches it and records it. It does not replace Claude Code, it drives it. The difference is not the model, it is what surrounds the run.

Paměť, kterou commituješMemory you commit

Nálezy, rozhodnutí a stránky specialistů leží v .agency/knowledge/ jako markdown. Přečte to kolega, přečte to obyčejná session, přečteš to ty za rok.

Findings, decisions and the specialists' own pages live in .agency/knowledge/ as markdown. A colleague reads it, a plain session reads it, you read it a year later.

Brána, která odmítáA gate that refuses

Nález ukazující na soubor, který na tom commitu neexistuje, se zahodí. Deterministicky, bez druhého modelu.

A finding pointing at a file that does not exist at that commit is dropped. Deterministically, with no second model involved.

Čísla místo dojmuNumbers, not impressions

Kolik nálezů se ukázalo jako pravda — po dimenzích, po modelech, po verzích metody.

How many findings turned out to be true — by dimension, by model, by version of the method.

„Vždyť si napíšu skill.““I can just write a skill.”

Můžeš, a je to správný začátek — pack je skill. Rozdíl je v tom, co se stane, když běh skončí.

You can, and it is the right start — a pack is a skill. The difference is what happens when the run ends.

PoctivěHonestly

Na jednorázovou práci je skill lepší — je jednodušší a stačí. Agency dává smysl, až když má někdo dělat tutéž práci znovu a znovu nad tímtéž repozitářem a ty chceš vědět, jestli se to zlepšuje.

For one-off work a skill is better — it is simpler and it is enough. Agency starts to pay off when someone has to do the same work again and again over the same repository and you want to know whether it is improving.

Jak běh probíháHow a run works

Jeden příkaz, pět fází. Model dělá jen tu prostřední.

One command, five phases. The model only does the middle one.

agency run review-graph --pr 479 --unattended --wait
  1. Příprava Nástroj postaví jednorázový worktree na commitu toho PR, dotáhne z code grafu, čeho se změna dotýká, a přiloží paměť projektu — co už se kdy našlo, čeho se to týkalo a co bylo zamítnuto. Nic z toho nedělá model.
  2. Běh Spustí se agent. Nedostane jen prompt, ale i seznam příkazů, které smí pustit, a jednu větu navíc v system promptu: tohle projekt už jednou zamítl, nehlas to znovu.
  3. Brána Co agent napsal, projde deterministickou kontrolou. Neexistující soubor, řádek za koncem souboru, chybějící důkaz, citovaný příkaz, který ve skutečnosti neproběhl — všechno se zahodí i s důvodem. Nic se nemaže, jen se to neposílá dál.
  4. Rozhodnutí Co branou projde, jde na tvůj board — nebo, když žádný nemáš, zůstane v commitované paměti. Ty (nebo druhý specialista) řekneš ano/ne, a u „ne“ jeden z pěti důvodů.
  5. Paměť Tvoje rozhodnutí se zapíše do stopy, která se commituje. Příští běh ho dostane na vstupu. Tady se z nástroje stává něco, co se učí.
  1. Preparation The tool builds a throwaway worktree on that PR's commit, pulls the blast radius out of the code graph, and attaches the project's memory — what has been found before, where, and what was rejected. None of this is done by a model.
  2. The run The agent starts. It gets more than a prompt: the list of commands it is allowed to run, and one extra sentence in its system prompt — this project already rejected these, do not report them again.
  3. The gate What the agent wrote goes through a deterministic check. A file that does not exist, a line past the end of it, missing evidence, a cited command that never actually ran — all dropped, each with a reason. Nothing is deleted, it just does not go further.
  4. The decision What passes goes to your board — or, if you have none, rests in the committed memory. You (or a second specialist) say yes or no, and for “no”, one of five reasons.
  5. Memory Your decision is written into a committed trail. The next run gets it as input. This is where a tool turns into something that learns.
Dohled, ne autopilotSupervision, not autopilot

Výchozí běh je pod dohledem: vidíš ho v terminálu a můžeš zasáhnout. Bez dozoru běží, jen když si o to řekneš — a i pak platí, že pack smí spustit jen příkazy, které má vypsané ve svém pack.json.

The default run is attended: you see it in the terminal and can step in. It runs unsupervised only when you ask for it — and even then a pack may only run the commands listed in its own pack.json.

Dvě věci, na kterých to celé stojíThe two things it all stands on

Brána, která je schválně hloupáA gate that is deliberately dumb

Brána nehodnotí, jestli je nález chytrý. Ptá se jen, jestli vůbec může být pravdivý. Halucinovaná cesta k souboru je poznat bez modelu — a model hlídající model stojí dvakrát tolik a je půlkou tak spolehlivý.

Proto je deterministická a proto se dá opakovat: dva lidé nad týmž během dostanou týž výsledek. A nic nemizí — zahozený nález si i s důvodem leží vedle, aby se dalo přezkoumat, jestli brána nezahazuje zbytečně.

The gate does not judge whether a finding is clever. It only asks whether it can be true at all. A hallucinated file path is recognisable without a model — and a model watching a model costs twice as much and is half as reliable.

That is why it is deterministic and repeatable: two people over the same run get the same result. And nothing disappears — a dropped finding rests beside the run with its reason, so you can check whether the gate is dropping too much.

Paměť, která patří projektuMemory that belongs to the project

Všechno, co si specialista „pamatuje“, je commitovaný markdown ve tvém repozitáři. Ne databáze, ne cloud, ne soubor v tvém domovském adresáři.

Má to tři důsledky, které stojí za to říct nahlas: přečte to kdokoli i bez tohohle nástroje; jde to revidovat v pull requestu jako každou jinou změnu; a když nástroj zítra zahodíš, paměť ti zůstane.

Everything a specialist “remembers” is committed markdown in your repository. Not a database, not a cloud, not a file in your home directory.

Three consequences worth saying out loud: anyone can read it without this tool; it can be reviewed in a pull request like any other change; and if you drop the tool tomorrow, the memory stays yours.

Kdo pro tebe může pracovatWho can work for you

Tohle jsou specialisté, kteří už existují jako referenční kopie. Nejsou to hotové produkty pro tvůj projekt — jsou to vzory, protože každý z nich nese fakta o jednom konkrétním repozitáři.

These are the specialists that already exist as reference copies. They are not finished products for your project — they are patterns, because each one carries the facts of one specific repository.

review-graph

Recenzent pull requestu. Neptá se jen diffu — ptá se code grafu, co ta změna ještě zasáhne, co nemá test a co už nikdo nevolá.

A pull-request reviewer. It does not only ask the diff — it asks the code graph what else the change reaches, what has no test, and what nothing calls any more.

qa

Prochází běžící staging jako vypsaná persona v čistém prohlížeči. Každý nález nejdřív zreprodukuje, teprve pak napíše.

Walks the running staging app as a written-out persona in a clean browser. Every finding is reproduced before it is written down.

po

Product owner. Projde board proti plánu, rozhodne každou položku a rozhodnutí zapíše na board, ne do reportu.

A product owner. Walks the board against the plan, decides each item, and writes the decision onto the board, not into a report.

legal

Právní přehled proti tomu, co zákon skutečně říká, s citací z primárního zdroje. Hlásí i povinnosti, které si produkt vymyslel sám.

A legal pass against what the law actually says, citing the primary source. It also reports duties the product invented for itself.

ceo

Strategický partner zakladatele. Přečte roadmapu, pak web, navrhne nejvýš tři sázky a připraví, co se má odeslat.

A founder's strategy partner. Reads the roadmap, then the web, proposes at most three bets and drafts what needs sending.

verify

Druhý pár očí. Otevře kód pod nálezem někoho jiného a odvodí tvrzení znovu — z kódu, ne z textu nálezu. Sám nic nehlásí.

A second pair of eyes. Opens the code under someone else's finding and derives the claim again — from the code, not from the finding's words. It reports nothing of its own.

A pak je tu author, jediný, který je opravdu obecný: pack, který píše packy. Ten dostaneš rovnou.

And then there is author, the one that is genuinely generic: the pack that writes packs. You get that one out of the box.

Postav si vlastního specialistuBuild your own specialist

Nepíšeš JSON. Popíšeš, koho potřebuješ, a zbytek je rozhovor.

You do not write JSON. You describe who you need, and the rest is a conversation.

agency run author --prompt "hlídač databázových migrací —
  zajímá mě všechno, co se nedá vrátit zpátky"
agency run author --prompt "a watcher for database migrations —
  anything that cannot be rolled back"
  1. Přečte si projekt Jazyk, stack, CI, dokumentaci, jestli máš board, a hlavně co už tvoji stávající specialisté pokrývají — aby ti nový nehlásil totéž podruhé.
  2. Zeptá se jen na to, co v repu není Žádný dotazník. Ptá se na fakta, která se nedají vyčíst: kde běží staging, co je u vás „nevratné“, koho to má zajímat.
  3. Dohodne dimenze nahlas Tohle je ta důležitá část. Dimenze je jedna otázka, jejíž odpověď může vyjít nepravdivě. „Kvalita kódu“ není dimenze. „Migrace, která maže sloupec bez zálohy“ je.
  4. Napíše adresář A nechá ho necommitnutý ve tvém pracovním stromě. Review je git — přečteš si diff jako u každé jiné změny a commitneš, až se ti bude líbit.
  1. It reads the project Language, stack, CI, docs, whether you have a board, and above all what your existing specialists already cover — so the new one does not report the same thing twice.
  2. It asks only what the repo cannot answer No questionnaire. It asks for the facts that cannot be read: where staging runs, what “irreversible” means here, who should care.
  3. It agrees the dimensions out loud This is the part that matters. A dimension is one question whose answer can come back false. “Code quality” is not one. “A migration that drops a column without a backup” is.
  4. It writes the directory And leaves it uncommitted in your working tree. Git is the review — you read the diff like any other change and commit it when you are happy.
Proč to píše agentWhy an agent writes it

Protože pack je zdrojový kód, a psaní zdrojového kódu je práce pro agenta. Hodnota není v tom JSONu — ten by vygeneroval kdejaký template. Hodnota je v sekci Project facts a v dimenzích, a ty vzniknou jedině tím, že se někdo zeptá a ty odpovíš.

Because a pack is source code, and writing source code is an agent's job. The value is not the JSON — any template could emit that. The value is the Project facts section and the dimensions, and those only come out of somebody asking and you answering.

Harness: proč se ti specialisté zlepšujíThe harness: why these specialists improve

Do léta 2026 uměl nástroj říct větu „dimenze reuse: precision 0,2“. Ta věta byla pravdivá a nikam nevedla. Mezi číslem a lepší metodou nebyla žádná cesta kromě člověka, který si na to vzpomene, otevře SKILL.md a něco tam přepíše — a pak nemá jak zjistit, jestli pomohl.

Harness je vrstva, která tu cestu dodělala. Nedělá agenta autonomnějším; dělá ho kalibrovaným — a kalibrace je to, co si autonomii teprve zaslouží.

Until the summer of 2026 the tool could say “dimension reuse: precision 0.2”. The sentence was true and it went nowhere. Between a number and a better method there was no path except a person remembering, opening SKILL.md and editing something — with no way to tell afterwards whether it helped.

The harness is the layer that built that path. It does not make the agent more autonomous; it makes it calibrated — and calibration is what earns autonomy in the first place.

Ticho už není výsledekSilence is no longer a result

Běh, který narazil na vypnutý staging, to teď řekne — stav blocked a věta proč. Dřív to vypadalo stejně jako „poctivě jsem nic nenašel“.

A run that hit a dead staging server now says so — a blocked result with the reason. It used to look identical to “I looked and found nothing”.

Citace se ověřujeCitations get checked

Když nález tvrdí, že stojí na výstupu nějakého příkazu, nástroj ověří, že ten příkaz opravdu proběhl. Do té doby to bylo jen tvrzení.

When a finding claims to rest on a command's output, the tool checks that the command actually ran. Until now that was just a claim.

Druhá šance uvnitř běhuA second chance inside the run

Když agent napíše nález špatně, dozví se to ještě než skončí, a může to opravit. Dřív to brána zahodila až po jeho odchodu.

If the agent writes a finding badly, it hears about it before it finishes and can fix it. Previously the gate dropped it after the agent was gone.

Vidíš, co se dějeYou see it happening

Zacyklení, odmítané příkazy, běh přes vlastní rozpočet — řekne se to, když se to děje. I na telefon, když nejsi u počítače.

A loop, refused commands, a run past its own budget — you are told while it happens. On your phone too, if you are away from the machine.

Víš, co agent dostalYou know what the agent had

Každý běh si pamatuje otisk metody i pravidel domu. Takže „od úterý to soudí hůř“ je konečně zodpověditelná otázka.

Every run records a fingerprint of the method and of the house rules. So “it has judged worse since Tuesday” is finally an answerable question.

Čísla, která nelžouNumbers that do not lie

U každého čísla o ceně je napsané, z kolika běhů pochází. Průměr přes populaci, jejíž půlka data nemá, je horší než žádné číslo.

Every cost figure says how many runs it came from. An average over a population half of which has no data is worse than no number at all.

Smyčka, kvůli které to celé jeThe loop it is all for

Tři příkazy, a mezi nimi tvoje rozhodnutí. Tohle je celý mechanismus zlepšování — žádné skryté učení, žádný model, který se trénuje kdesi.

Three commands with your decisions in between. This is the whole improvement mechanism — no hidden learning, no model being trained somewhere.

agency metrics --for-author review-graph   1 · co ten pack dělá1 · what the pack does
agency run author --revise review-graph    2 · diff do SKILL.md2 · a diff into SKILL.md
agency replay --pack review-graph          3 · zhoršilo se něco?3 · did anything get worse?
  1. Brief, ne dashboard První příkaz nevypíše grafy. Vypíše, co je v metodě špatně: která dimenze má nízkou precision a dost rozhodnutých nálezů, aby to něco znamenalo, která už dvacet běhů nenašla nic, na čem nálezy nejčastěji padají, a příklady toho, co obstálo a co ne.
  2. Autor přepíše metodu Druhý příkaz pustí author v režimu revize. Dostane ten brief a napíše diff do SKILL.md. Ke každé změně musí umět ukázat řádek v briefu, který ji odůvodňuje — změna bez toho je změna vymyšlená. A pod deseti rozhodnutými nálezy vůbec nenastartuje.
  3. Přehrání to ověří Třetí příkaz pustí pack znovu nad tímtéž commitem s dnešní metodou a porovná to s tím, co jsi tehdy rozhodl. Jedno pravidlo je tvrdé a bez výjimek: vrátí-li se nález, který jsi už jednou zamítl, je to regrese a neprojde.
  1. A brief, not a dashboard The first command prints no charts. It prints what is wrong with the method: which dimension has low precision and enough decided findings for that to mean anything, which has found nothing in twenty runs, what findings most often fail on, and examples of what held up and what did not.
  2. The author rewrites the method The second runs author in revise mode. It gets the brief and writes a diff into SKILL.md. Every change has to point at the line in the brief that justifies it — a change that cannot is a change it invented. And below ten decided findings it refuses to start at all.
  3. Replay proves it The third runs the pack again over the same commit with today's method and compares against what you decided then. One rule is hard and has no exceptions: if a finding you already rejected comes back, that is a regression and it does not ship.
Proč zrovna takhleWhy this shape

Existují systémy, které si o agentovi vedou „instinkty“ s konfidencí 0,7 kdesi mimo tvůj repozitář. Ty ale nikdo nereviduje a nikdo je nepřečte. Diff v SKILL.md reviduješ v Source Control jako každou jinou změnu — a to je celý rozdíl mezi učením, kterému můžeš věřit, a učením, které musíš vzít na slovo.

There are systems that keep “instincts” with a confidence of 0.7 somewhere outside your repository. Nobody reviews those and nobody reads them. A diff in SKILL.md you review in Source Control like any other change — and that is the whole difference between learning you can trust and learning you have to take on faith.

Co Agency schválně neděláWhat Agency deliberately does not do

Tohle nejsou chybějící funkce. Jsou to rozhodnutí, a stojí za to je znát dřív, než se na ně narazí.

These are not missing features. They are decisions, and worth knowing before you run into them.

You need git, uv and Claude Code. A reviewer also needs gh and a code graph, QA needs Playwright's browsers — agency doctor tells you what is missing before a run.

Po prvním běhu tě zajímají tři příkazy: agency findings (co se našlo a kam to šlo), agency triage accept|reject (tvoje rozhodnutí — tohle je palivo celé smyčky) a agency metrics (jestli to k něčemu je).

Všechno jde i z VS Code panelu, kde nálezy sedí přímo u řádku kódu.

After the first run, three commands matter: agency findings (what was found and where it went), agency triage accept|reject (your decisions — this is the fuel for the whole loop) and agency metrics (whether it is worth anything).

All of it also works from the VS Code panel, where findings sit next to the line of code.

Otázky, které dostávámQuestions that come up

Nahrazuje to Claude Code?Does it replace Claude Code?

Ne, řídí ho. Claude Code (nebo Codex) je běhoun; Agency je to, co běh připraví, ohlídá, prožene bránou a zapamatuje si výsledek. Bez Claude Code Agency nespustíš.

No, it drives it. Claude Code (or Codex) is the runner; Agency is what prepares the run, watches it, puts the output through a gate and remembers the result. Without Claude Code there is nothing to run.

Posílá to někam moje data?Does it send my data anywhere?

Agency sama nikam. Běží lokálně, na tvém přihlášení, a všechno, co vyrobí, leží u tebe v repozitáři. Do modelu jde přesně to, co by šlo, kdybys Claude Code spustil ručně.

Agency itself, nowhere. It runs locally, on your own login, and everything it produces sits in your repository. What reaches the model is exactly what would reach it if you started Claude Code by hand.

Kolik to stojí?What does it cost?

Tolik, co běhy modelu — a od Fáze 12 to nemusíš odhadovat: agency metrics umí cenu na nález, který došel na board. Každý pack si navíc deklaruje, co je u něj normální běh, a nástroj řekne, když ho přeteče.

Whatever the model runs cost — and since Phase 12 you do not have to guess: agency metrics gives the price per finding that reached the board. Each pack also declares what a normal run costs it, and the tool says when a run goes over.

Co když tomu specialistovi nevěřím?What if I do not trust a specialist?

Pusť ho pod dohledem a nech ho zřetězit s verify. Za dva tři týdny máš čísla a nemusíš věřit ničemu — nedůvěra se dá změřit. A dokud pack nemá deset rozhodnutých nálezů, revize se ani nespustí, aby ses nezlepšoval podle náhody.

Run it attended and chain it with verify. In two or three weeks you have numbers and do not have to trust anything — distrust is measurable. And until a pack has ten decided findings, a revision will not even start, so you cannot “improve” it against noise.

Můžu ho pustit bez dozoru?Can I run it unsupervised?

Můžeš, ale je to volba, ne výchozí stav. Agency ti k tomu dá dvě věci, které jinde chybí: pack smí jen příkazy, které má vypsané, a běh bez dozoru umí říct, že narazil na zeď, místo aby doběhl do ticha.

You can, but it is a choice, not the default. Agency gives you two things others do not: a pack may only run the commands it lists, and an unsupervised run can say it hit a wall instead of finishing into silence.

Co když projekt nemá board?What if the project has no board?

Nic se neděje. Nálezy zůstanou v commitované paměti a kanálem je git. Pack bez sink je normální stav, ne nedodělek.

Nothing breaks. Findings rest in the committed memory and git is the channel. A pack with no sink is a normal state, not an unfinished one.
